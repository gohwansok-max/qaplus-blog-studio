# QA PLUS Blog Studio

QA PLUS 유튜브 영상을 Blogger용 식품안전 실무 글로 바꾸고, 검토 후 임시저장 또는 발행하는 단일 HTML PWA입니다.

**v21부터 파이프라인·설정 구조를 경제냠냠 블로그 스튜디오와 동일하게 맞췄습니다.** 화면 색과 QA PLUS 브랜딩은
그대로 두고, 그 아래에서 돌아가는 호출 방식·이어쓰기·체크포인트·설정 항목을 경제냠냠 쪽으로 통일했습니다.

상단에 현재 배포 버전(`APP v21`)이 항상 표시됩니다. **새로고침**을 누르면 전용 업데이트 화면이 기존 서비스워커와
QA PLUS 앱 캐시만 정리한 뒤 최신 버전을 다시 엽니다.

## 6단계 파이프라인

| 단계 | 하는 일 | 모델 |
|---|---|---|
| 1 | 영상 보고 대본 뽑기 | `gemini-3.6-flash` |
| 2 | 취재하고 설계하기 (목차·근거·표 계획) | `gpt-5.6-sol` |
| 3 | 본문 집필 | `claude-opus-4-8` |
| 4 | 보강하고 살 붙이기 | `claude-opus-4-8` |
| 5 | 제목·검색설명·라벨·실사 이미지 | `gpt-5.6-sol` + `gpt-image-2` |
| 6 | Blogger 임시저장 또는 발행 | — |

기본값은 글 길이 **9,000자**, 이미지 **대표+본문 3장**입니다. 설정에서 바꿀 수 있습니다.

### 왜 이 구조가 더 안정적인가

- **호출 경로가 하나입니다.** 2~5단계가 전부 칩섭 `chat/completions` SSE 스트리밍 한 가지 방식만 씁니다.
  Claude 전용 Anthropic `/v1/messages` 경로, 모델별 예비 전환(Opus→Sonnet→ChatGPT), 확장 패스 카운터는
  모두 없앴습니다. 실패 지점이 줄어드니 원인 파악도 쉬워집니다.
- **잘리면 이어서 씁니다.** 출력 한도로 글이 끊기면 마지막 글자 다음부터 자동으로 이어 쓰고,
  겹쳐 나온 문장은 최대 600자 범위에서 자동 제거합니다(`joinContinuation`).
- **끊겨도 이미 쓴 건 안 버립니다.** 스트림이 중간에 죽어도 받은 만큼은 살려 두고 이어서 재개합니다.
- **단계별 체크포인트.** 대본·설계도·1차 원고·보강 원고·생성된 이미지를 각각 `localStorage`에 저장합니다.
  집필·보강 중에는 약 2.5초 간격으로 부분 원고도 저장합니다. 3단계에서 실패했다면 다시 실행해도
  **1·2단계는 다시 결제하지 않고 저장본을 복구**합니다.
- **모바일 백그라운드 복구.** 다른 앱으로 이동해 연결이 끊기면 화면으로 돌아올 때까지 기다렸다가
  지수형 대기 후 최대 6회 재시도합니다. 실행 중에는 Screen Wake Lock으로 화면 꺼짐을 막습니다.
- **이미지는 성공한 장만 보존.** 실패한 슬롯만 이어서 다시 만들고, 같은 슬롯을 다시 실행해도
  본문 이미지가 중복되지 않습니다. 일시 오류는 장당 최대 3회 확인합니다.

### 이미지 경로

`설정 → 이미지 생성 → 어디서 그릴까요`에서 고릅니다. 기본은 **자동**이며 순서대로 시도하고,
실패하면 경로별 사유를 함께 보여 줍니다.

1. **QA PLUS 중계(칩섭)** — 워커가 KV에 영구 보관한 HTTPS 주소를 돌려주므로 PC 캐시에 의존하지 않고
   스마트폰에서도 보입니다.
2. **OpenAI 직접** — 브라우저에서 바로 호출합니다. 워커가 홍콩 콜로에서 실행돼 OpenAI 지역 차단
   (`unsupported_country_region_territory`)에 걸릴 때의 우회 경로입니다.
3. **OpenAI 프록시** — 워커 경유.

2·3번으로 받은 이미지가 base64뿐이면 GitHub 토큰이 설정된 경우 이 저장소 `blog-images/` 폴더에 올리고
주소만 본문에 넣습니다. 토큰이 없으면 글 안에 직접 넣습니다(파일이 커져 발행이 실패할 수 있습니다).

### QA PLUS 전용으로 유지한 것

파이프라인 골격은 경제냠냠과 같지만, 아래는 QA PLUS 그대로입니다.

- 프롬프트 페르소나: 20년 경력 식품안전 편집장. 독자는 현장 품질·생산·위생 담당자.
- **대본과 공식 출처에 없는 법령 번호·기준 수치·처벌 조항·인증 요구사항을 만들지 않습니다.**
  확실하지 않으면 "확인이 필요합니다"로 표시합니다.
- 공식 출처 입력칸 — 여기 넣은 주소만 참고자료로 씁니다.
- 본문에 YouTube `youtube-nocookie` 임베드, QA PLUS 무료자료 CTA, 면책 문구를 자동 포함합니다.
- 실사 B-roll 규칙 — 분야별 장면(생산 현장/위생 전실/기록 확인 등), 카메라 거리 3종 분리,
  글자·로고·얼굴 없는 네거티브 프롬프트.
- 발행 전 검사, 같은 영상 중복 발행 방지, 임시저장 기본값.

## 처음 한 번 설정하기

설정은 **입력하는 즉시 이 기기에 저장**됩니다(`localStorage` + IndexedDB). 탭을 닫아도 남습니다.
공용 PC에서는 키를 입력하지 마세요. 다 쓴 뒤에는 `설정 → 저장 상태 → 전체 지우기`로 지울 수 있습니다.

경제냠냠과 같은 브라우저 프로필을 쓰신다면 **경제냠냠 설정 가져오기** 버튼으로 칩섭 키, 제미나이 키,
OpenAI 키, GitHub 토큰, OAuth Client ID를 한 번에 불러올 수 있습니다(비어 있는 칸만 채웁니다).

### 0. API 다리(프록시)

칩섭과 OpenAI는 브라우저에서 직접 호출이 막혀 있습니다(응답에 CORS 헤더를 주지 않음).
QA PLUS 전용 워커가 이미 배포되어 있으므로 기본값 `https://qa-plus-api.gohwansok.workers.dev`를
그대로 쓰시면 됩니다. 직접 만들려면 `qa-plus-api-worker.js`를 Cloudflare Worker로 올리세요.

### 1. CheapSub API 키

`csk_`로 시작하는 키를 발급하고 크레딧을 충전한 뒤 넣습니다. 2~5단계가 모두 이 키를 씁니다.

### 2. Google Gemini API 키

Google AI Studio에서 발급합니다. 공개 영상만 자동 추출되며, 비공개·일부공개 영상은 승인 대본을 직접 넣으세요.
대본 추출은 Google 서버의 백그라운드 작업으로 돌기 때문에 화면이 꺼져도 계속되고, 앱으로 돌아오면 이어받습니다.

### 3. OpenAI API 키 (선택)

칩섭 이미지 경로가 막혔을 때만 씁니다. GPT Image 계열은 OpenAI 콘솔에서 **조직 인증**을 마쳐야 하며,
인증 전이면 모델을 `dall-e-3`으로 고르세요.

### 4. GitHub 토큰 (선택)

Settings → Developer settings → **Fine-grained token** → 이 저장소 선택 → **Contents: Read and write**만
켜면 됩니다.

### 5. Google OAuth

Blogger 임시저장·발행에만 씁니다(AI 생성에는 쓰지 않습니다). 승인된 JavaScript 원본에 GitHub Pages 배포
주소를 등록하고 Blogger API를 활성화한 뒤 **Google 로그인**을 누르세요. 토큰은 메모리에만 유지되므로
새로고침하면 다시 연결해야 합니다. 기본 발행 모드는 안전을 위해 항상 **임시저장**입니다.

### 6. YouTube Data API 키 (선택)

**내 영상** 버튼으로 `@qaplus_haccp` 최신 영상 목록을 불러올 때만 씁니다. 채널 ID를 비워 두면 핸들로 자동 조회합니다.

### 7. 전체 연결 검증

프록시 → 칩섭 → 제미나이 → 이미지 → GitHub → Blogger 순서로 실제 응답까지 확인합니다.
Blogger에 글을 만들지는 않지만, 칩섭 텍스트 요청과 이미지 1장 생성 비용은 발생합니다.

## 블로그 도구

- **이미 올린 글 고치기** — Blogger 테마는 글 안의 `<table>`에 테두리를 그려 주지 않아 표가 그냥 글처럼
  보이고, 넓은 표는 화면 밖으로 삐져나갑니다. 기존 글 HTML을 붙여넣으면 표·이미지·인용문에 인라인 스타일을
  입혀 돌려줍니다. 테마 CSS로 한 번에 고치는 방법도 화면에 안내되어 있습니다.
- **필수 페이지 자동 생성** — 블로그 소개, 개인정보처리방침, 문의하기, 저작권 및 면책조항 4개를 만들어
  Blogger 페이지로 바로 올립니다.

## 보안 원칙

- API 키와 OAuth 토큰을 HTML 소스나 주소에 넣지 않습니다.
- API 키는 이 기기의 브라우저 저장소에만, Google OAuth 토큰은 메모리에만 유지됩니다.
- 중계 워커는 요청 경로만 전달하며 API 키·요청 본문·생성 결과를 저장하지 않습니다.
- 실제 회사명, 제품명, 개인정보가 포함된 대본은 익명화한 뒤 전송하세요.

## 로컬 실행과 테스트

빌드 과정이 없습니다.

```bash
py -m http.server 4173
```

그다음 `http://localhost:4173/`을 엽니다.

테스트는 Node 내장 러너 없이 파일을 직접 실행합니다.

```bash
node tests/stability-characterization.test.mjs && node tests/blogger-publish.test.mjs && node tests/image-persistence-worker.test.mjs
```

`stability-characterization.test.mjs`는 위에 적은 안정성 계약(단일 호출 경로, 이어쓰기, 체크포인트,
설정 항목, 이미지 경로 순서, 버전 일치)을 고정합니다. 리팩터링으로 이 성질이 사라지면 실패합니다.

## 배포

GitHub Pages에서 `main` 브랜치의 `/ (root)`를 배포 소스로 선택합니다.
워커는 `wrangler deploy`로 따로 배포합니다.

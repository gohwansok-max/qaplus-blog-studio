.post-body table{display:block;max-width:100%;overflow-x:auto;border-collapse:collapse}
.post-body table th,.post-body table td{border:1px solid #d7e3e5;padding:10px 12px}
.post-body table th{background:#eaf6f3;font-weight:700}

검증 전

0. 가장 먼저 — API 다리(프록시) 주소

칩섭과 OpenAI는 브라우저에서 직접 못 부릅니다. 이 다리를 한 번 만들어 두면 끝납니다.

확인 전
QA PLUS 전용 다리는 이미 배포되어 있습니다. 기본값 그대로 쓰시면 됩니다.
직접 만들려면 ① cloudflare.com → Workers → Create → Worker → ② qa-plus-api-worker.js 내용 붙여넣기 → Deploy → ③ 나온 주소를 위 칸에 넣기. 하루 10만 건까지 무료입니다.

1. 서버 작업실 — 브라우저 없이 계속 실행

글 생성은 서버가 맡고, 이 화면은 진행 상황만 확인합니다.

확인 전

AI API 키가 아닙니다. 내 서버 작업을 보호하는 전용 키입니다.

2. 칩섭(CheapSub) — 기존 직접 연결 점검용

설계·집필·보강 3단계를 모두 같은 방식으로 호출합니다.

확인 전

칩섭 대시보드에서 발급합니다.

공급자 장애로 이 모델이 막히면(fixed_merchant_unavailable) 같은 계열의 다음 모델로 자동 전환하고 결과 화면에 알려 드립니다.

글 생성용 API 키는 서버에만 보관합니다. 아래 ‘서버 작업실 접근 키’는 이 앱에서 서버 작업을 시작할 때만 쓰므로 공용 PC에는 저장하지 마세요.

3. 제미나이 — 기존 직접 연결 점검용

유튜브 주소만 주면 영상을 직접 보고 받아씁니다.

확인 전

Google AI Studio에서 무료로 발급합니다.

모델 이름이 안 맞으면 위 순서대로 자동으로 다시 시도합니다. 화면이 꺼져도 구글 서버에서 계속 실행되고, 돌아오면 이어받습니다.

4. 이미지 생성

QA PLUS 중계로 먼저 시도하고, 안 되면 OpenAI로 넘어갑니다.

확인 전
프록시 경유가 막히는 경우
클라우드플레어 워커가 홍콩 데이터센터에서 실행되면 OpenAI가 지역 차단(unsupported_country_region_territory)을 겁니다. 워커나 계정 문제가 아니라 워커가 어디서 실행됐느냐의 문제입니다. 그래서 브라우저 직접 호출 경로를 함께 넣어 두었습니다.

GPT Image 계열은 OpenAI 콘솔에서 조직 인증을 마쳐야 씁니다. 인증 전이면 dall-e-3 을 고르세요.

5. 이미지 보관 위치

만든 그림을 어디에 두고 블로그에서 불러올지 정합니다.

확인 전
QA PLUS 중계로 만든 그림은 이미 영구 주소를 받으므로 그대로 씁니다.
OpenAI 직접 호출로 받은 그림만 이 저장소 blog-images/ 폴더에 올라갑니다.
GitHub → Settings → Developer settings → Fine-grained token → 이 저장소 선택 → Contents: Read and write 만 켜면 됩니다.
